Running the Full Stack on a Virtual Machine

ROS2 Jazzy + Gazebo Harmonic need Linux. This walks through setting up a VM and running this repo's own install scripts in it — nothing new invented, just scripts/*.sh already in the repo, in the right order.

Why a VM at all: this repo's Windows checkout can't run colcon build or launch Gazebo directly — those need Ubuntu. A VM (or WSL2, or dual-boot) is the way to get a real Linux environment. Earlier project backups in this repo's history reference a VirtualBox user (vboxuser), so VirtualBox is what this project has used before — this guide follows that.

1 Install VirtualBox & create the VM

  1. Install VirtualBox (and the Extension Pack) if not already installed.
  2. Download Ubuntu 24.04 LTS "Noble Numbat" desktop ISO — this is the OS version ROS2 Jazzy and the repo's install scripts target (scripts/setup_ros2_repo.sh explicitly adds the noble ROS2 apt repo).
  3. Create a new VM: Type Linux, Version Ubuntu (64-bit).
  4. Give it real resources — Gazebo is not lightweight:
    ResourceMinimumRecommended
    RAM4 GB8 GB+
    CPU cores24+
    Disk25 GB40 GB+
  5. In the VM's Display settings, set Video Memory to the max (128 MB) and enable 3D Acceleration — needed if you want the actual Gazebo GUI window rather than headless mode.
  6. Install Ubuntu normally, then install Guest Additions (VirtualBox menu: Devices → Insert Guest Additions CD) for better display/clipboard/shared-folder support.

2 Get the repo onto the VM

Inside the Ubuntu VM, open a terminal:

sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/rakshithachannakeshav/lunar-rover-quantum.git ~/lunar-rover-quantum
cd ~/lunar-rover-quantum
The repo root is the ROS2 workspace now — src/ sits directly at the repo root, there's no separate lunar_rover_ws/ subfolder to cd into. Every path below assumes you're standing in ~/lunar-rover-quantum.

3 Run the install scripts, in order

These already exist in scripts/ — just run them one at a time. Each does real apt-get work and will take several minutes; read each one first if you want to know exactly what it does.

chmod +x scripts/*.sh

# 1. ROS2 apt repo + locale setup
bash scripts/setup_ros2_repo.sh

# 2. ROS2 Jazzy desktop + colcon + rosdep
bash scripts/install_ros2_jazzy.sh

# 3. Gazebo Harmonic + ros_gz bridge
bash scripts/install_gazebo_harmonic.sh

# 4. Extra simulation deps (xacro, rviz2, nav2, teleop, tf tools...)
bash scripts/install_sim_dependencies.sh

# 5. Python + Qiskit/quantum stack (creates a venv)
bash scripts/install_python_quantum.sh
Heads up: install_ros2_jazzy.sh and install_python_quantum.sh hardcode /home/monis/.bashrc (a specific person's username from before this repo was reorganized) instead of your actual home directory. If your VM user isn't named monis, those specific "add sourcing to .bashrc" lines will silently do nothing — harmless, but it means new terminals won't auto-source ROS2. Just run source /opt/ros/jazzy/setup.bash manually each new terminal, or fix that one line yourself if it bothers you.

4 Build the workspace

source /opt/ros/jazzy/setup.bash
cd ~/lunar-rover-quantum
colcon build --symlink-install
Expect: colcon reports building evaluation_pkg, mapping_pkg, navigation_pkg, planning_pkg, rover_simulation, sensor_pkg — all should say Finished, none Failed. The four scaffolding packages (mapping/planning/navigation/evaluation) have no real nodes yet, so they'll build near-instantly since there's nothing to compile.

5 Launch the simulation

source install/setup.bash
ros2 launch rover_simulation simulation_launch.py
Expect: Gazebo starts headless by default (no window) — this is intentional, see the comment at the top of src/rover_simulation/launch/simulation_launch.py. You'll see log lines and a reminder on how to attach a GUI or RViz.

To see something visually, either:

  • Attach the Gazebo GUI (needs 3D acceleration working) — in a second terminal: bash scripts/open_gazebo_gui.sh
  • Or use RViz instead (usually more VM-friendly than Gazebo's own renderer): 
    ros2 launch rover_simulation demo.launch.py mode:=creep use_rviz:=true
If the Gazebo GUI crashes or the window stays black, that's almost always a 3D-acceleration problem in the VM, not a bug in the code — RViz is the fallback path and is what the scripts' own comments recommend when running under a VM/WSL.

6 Sanity-check it's actually running

In another terminal (remember to source install/setup.bash in every new terminal):

ros2 topic list
ros2 topic echo /odom --field pose.pose.position
Expect: /odom, /cmd_vel, /scan, /imu/data, /joint_states, /tf among the topics; the odom echo prints a position that changes if you drive the rover (see below).

Drive it manually:

ros2 run rover_simulation rover_keyboard.py

Or run the sensor nodes (separately, this is sensor_pkg, not rover_simulation):

ros2 launch sensor_pkg sensors_launch.py

SymptomLikely cause
gz sim --version failsGazebo install step didn't complete — re-run install_gazebo_harmonic.sh
colcon build fails on a specific packageMissing rosdep — try rosdep install --from-paths src --ignore-src -r -y from the repo root
Gazebo GUI window is black/crashes3D acceleration not working in the VM — use RViz instead (Step 5)
ros2: command not foundForgot to source /opt/ros/jazzy/setup.bash in this terminal
